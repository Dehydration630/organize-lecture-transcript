# 整理课堂转写

把课堂转写中的有效知识重新组织成清晰笔记，同时保留原文的知识边界。不要把常识、外部资料或自己的推断补写成课堂内容。

## 运行环境分流

- 在 ChatGPT 网页端或不具备本机终端、文件系统和剪贴板权限的环境中，直接使用当前平台提供的模型整理用户粘贴或上传的转写稿。不要运行本地脚本、访问用户剪贴板、调用 DeepSeek API 或索要 API 密钥。
- 在本地 Codex 或终端环境中，用户直接粘贴或上传转写稿时，仍在当前对话中整理并返回 Markdown。
- 仅当处于本地环境且用户明确要求监听剪贴板、处理本地文件或批量处理时，运行 `scripts/run.py`。相对路径均以本 Skill 目录为基准。
- 无法确定运行环境时，采用网页安全模式：只处理用户主动提供的内容，不调用脚本或外部 API。
- 需要确认目标排版或进行测试时，读取 `references/example.md`。不要把示例中的具体知识带入其他课程。

## 整理流程

1. 通读全文，判断主要课程主题、知识主线和文稿完整程度。
2. 删除时间戳、噪音标签、无意义语气词、机械重复和与课程无关的闲聊。
3. 保留有助于理解的师生问答、例子、推导、条件、限定语和教师强调。
4. 合并散落在不同位置但属于同一主题的信息，不按原始发言顺序机械抄写。
5. 区分原文事实、明显转写错误和无法确定的内容：
   - 仅在上下文只有一种合理解释时修正明显错字。
   - 无法可靠修正时写入“待核实内容”，不要猜测。
   - 文稿明显从中间开始、突然结束或缺失关键上下文时，将文稿质量标为“可能残缺”。
6. 输出最终 Markdown，不输出分析过程、JSON、代码围栏或额外寒暄。

## 内容边界

- 只整理原文明确表达或可由同一段上下文直接推出的内容。
- 不补充原文未出现的定义、公式、人物、日期、案例、结论或参考资料。
- 不把学生未经教师确认的猜测写成确定结论。
- 不因追求完整而虚构缺失步骤。使用“原文未说明”“此处转写不清”或“待核实”。
- 保留否定、例外、适用条件和程度词，避免改变原意。
- 精简表达但不要压缩掉论证关系和关键细节。

## 输出格式

严格使用以下基础结构：

```markdown
# 课程主题

> 文稿质量：正常 / 可能残缺
> 整理说明：一句话说明覆盖范围；无特殊情况可省略本行

## 核心结论

- 3～7 条最重要结论

## 知识笔记

### 知识点一

用段落和列表说明定义、关系、条件、步骤或推导。

### 知识点二

继续按主题组织。

## 课堂示例

仅记录原文中实际出现且有学习价值的例子。

## 教师强调与易错点

- 记录教师反复强调、对比或纠正的内容。

## 待核实内容

- 记录无法可靠识别或缺失上下文的内容。

## 复习清单

- 使用可执行的问题或任务帮助复习。
```

始终保留“核心结论”“知识笔记”和“复习清单”。没有可靠内容时，省略“课堂示例”“教师强调与易错点”或“待核实内容”，不要用“无”填充。根据内容自然增加三级标题，不要增加与课程无关的通用章节。

## 本地自动化脚本

仅在具备本机终端权限且用户明确选择本地自动化时使用本节。默认调用 DeepSeek 官方的 `deepseek-v4-flash`。在运行非试验请求前，从环境变量读取配置：

- `DEEPSEEK_API_KEY`：DeepSeek 官方 API 密钥；优先读取且不得写入文件。
- `LECTURE_NOTES_API_KEY`：通用备用密钥变量；未设置时继续兼容读取 `OPENAI_API_KEY`。
- `LECTURE_NOTES_MODEL`：模型名称；默认使用 `deepseek-v4-flash`。
- `LECTURE_NOTES_BASE_URL`：兼容 Chat Completions 的基础地址；默认使用 `https://api.deepseek.com`。
- `LECTURE_NOTES_OUTPUT_DIR`：笔记目录；默认使用 `~/Documents/LectureNotes/output_notes`。

按需求选择命令：

```bash
python3 scripts/run.py watch
python3 scripts/run.py file /path/to/transcript.txt
python3 scripts/run.py batch /path/to/transcripts
```

监听模式仅支持 macOS，并默认要求文本达到长度阈值且具有时间戳、发言人或噪音标签等转写特征。仅在用户明确要求接受任意长文本时使用 `--accept-any-long-text`。仅在用户明确选择后使用 `--copy-result` 或 `--open-result`。

不要把 API 密钥写入 Skill 文件、脚本、日志或命令参数。不要在日志中记录完整转写文本。
